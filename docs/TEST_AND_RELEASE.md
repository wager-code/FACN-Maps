# Steam SCFA 地图测试、发布与回滚标准

这是一套 **Codex 和人工共同执行** 的验收清单。静态核验、脚本可加载、单机能玩、多人同步、实际可发布是五个不同级别，**不得互相替代**。

## A. 接收和备份（动任何地图前）

- [ ] 记录来源、原作者、发布许可或授权情况、下载地址、原始 ZIP SHA-256、地图文件夹名、Steam 目标版本。
- [ ] 保留用户提供的原始压缩包只读副本；修复版放在独立工作分支/目录。
- [ ] 计算每个文件的 SHA-256；不随意修改或重编码二进制 .scmap/.luac。
- [ ] 从原地图读出目录结构、ScenarioInfo、资源/标记数、军队/出生点数、依赖文件清单。
- [ ] 明确所需引擎/第三方 MOD；无法核实标记“未知”。

## B. 结构与 Lua 静态检查

- [ ] `_scenario.lua` 中 `map` / `save` / `script` 指向实际文件；大小写、目录名一致。
- [ ] `_save.lua` 中军队、初始单位、地图标记以及特殊敌军/友军与 Scenario 定义一致。
- [ ] 找出所有 `import()`；逐个验证 Steam VFS 中存在，不依赖“FAF 里有就行”。
- [ ] 找出所有单位蓝图 ID；验证所选难度/阵营/波次分支中的 Steam 原版支持。
- [ ] `_options.lua` 的 `key`、`pref`、`default`、`values[].key` 与实际脚本消费对齐。
- [ ] `OnPopulate`、`OnStart`、胜负判定、辅助线程、波次触发无显然 nil/越界/重复启动。
- [ ] 对于 `.luac`，记录字节码兼容性风险，不伪造可解码源。
- [ ] 对非标准 FA Lua 方言使用引擎兼容检查；普通 Lua 检查器只是辅助，不能替代游戏实测。

## C. Steam 原版实机必测

测试条件：明确 Steam 安装/构建信息；初次测试 **不启动 FAF 客户端、不加载额外 MOD**（除非已明确标记“有依赖”），地图从标准目录或实际配置的地图目录加载。

| 用例 | 预期 | 证据 |
| --- | --- | --- |
| C1 地图大厅可见 | 地图正确显示名称、缩略图、玩家槽位；不会退回默认地图 | 截图+日志 |
| C2 默认选项启动 | 不报错，玩家与指挥官正确生成 | 日志+截图 |
| C3 自定义选项可见 | 目标 Steam 大厅有真实 UI 入口（如设计要求） | 截图 |
| C4 选项确实生效 | 改一次选项后，脚本观测值和实际玩法变化一致 | 两次对照日志 |
| C5 生成/波次 | 第一波正常，至少检查 T2/T3/特殊波次出现时的蓝图和行为 | 时间点+截图 |
| C6 指挥官与工程师 | 正确阵营、数量、位置，关闭选项时不额外生成 | 对照测试 |
| C7 胜负判定 | 指挥官存活/死亡、保护目标存活/毁灭、时间结束分别正确 | 结束画面+日志 |
| C8 连续运行/性能 | 无逐波性能恶化、无限线程、过多模拟单位 | 时段记录 |
| C9 最少玩家及空槽 | 不会为无人槽位生成多余玩家单位或对 nil Brain 操作 | 回归日志 |
| C10 MOD 依赖 | 无 MOD 运行结果或明确的依赖声明；不能凭一轮结果说完全兼容 | MOD 清单+日志 |

## D. 多人 / 模式矩阵

在机器/人员条件允许时，按以下组合覆盖；无法执行的明确写“未测试”：

- [ ] 1人：默认 / 非默认选项；
- [ ] 2人：不同阵营、不同出生位置，胜负逻辑；
- [ ] 4人（地图允许时）：混合阵营、有人死亡、有人退出、不同玩家槽位；
- [ ] 空槽、不按顺序选槽、非满员开始；
- [ ] 开局生成额外工程师/ACU/SACU 的开关、最高数量和关闭选项；
- [ ] 自适应难度/计时器/独立玩家敌军在多人端一致；
- [ ] 短刷怪间隔、长时间持续运行、后期大量单位压力；
- [ ] 原版与整合版相同选项的 A/B 对照。

## E. 日志与复现模板

启动参数可在当前游戏版本**确认支持**后尝试 `/showlog` 和 `/log`，采用单独且可写的日志目录；不要直接复制他人固定 Steam/FAF 路径。

```text
地图文件夹:
归档来源/原始 SHA-256:
Steam 构建及 exe 路径:
Windows 版本:
MOD: 无 / 清单:
游戏人数和军队槽位:
地图设置 key=value:
复现时间点/波次:
预期结果:
实际结果:
错误栈（原始日志）:
代码位置:
修复 commit / PR:
静态检查:
Steam 单机:
Steam 多人:
是否还有阻塞:
```

记录 *第一个根因性报错*，不要只保留后续连锁报错；日志可能包含用户名/机器路径，公开仓库提交前先清理私人信息，不应隐藏诊断所必需的错误行。

## F. 版本去重与合并验收

- [ ] 分别计算原版/整合版哈希，并提交清晰差异报告。
- [ ] 地形相同但玩法不同的版本，核对阵营波次表、难度、AI、胜利条件和自带第三方库。
- [ ] 整合后的每种模式都与原地图对应玩法进行 A/B 实机对照。
- [ ] 未整合成功或存在冲突的玩法仍提供独立地图版本。
- [ ] 不覆盖唯一原始包；旧版必须能通过版本档案回滚。
- [ ] 删除/下架旧版必须有明确列表与审核理由，不能自动执行。

## G. 发布至 FACN 地图中心前

- [ ] 经过审阅，并核对作者信息和发布许可；不把第三方版权地图未经许可当作自有作品分发。
- [ ] 正式包不包含无引用的 .git 元数据/临时文件，但保留需要的 Lua/src/vendor/图像/SCMAP。
- [ ] 地图目录和内部路径一一对应；Windows 安装/更新流程可正常放入正确地图目录。
- [ ] 资源清单记录：显示名称、唯一地图 ID（需设计）、版本、包大小、校验哈希、Steam 兼容状态、可选 MOD 依赖。
- [ ] 发布前检查下载完整性、自动更新版本冲突、同名地图与目录碰撞、回滚恢复。
- [ ] 用户端能清楚看到“Steam 已实测 / 仅静态通过 / 需要 MOD / 不兼容”状态。
- [ ] 只有**运行证据充足**且发布条件满足时，标记 `已发布`。
