# AI 制作地图与玩法：可行范围和实施方法

研究对象是2026-10-16删除专用模组图后保留的62张。逐图入口见[代码地图册](SURVIVAL_CODE_ATLAS_2026-10-16.md)，本轮实际修正见[维护报告](CODE_MAINTENANCE_2026-10-16.md)。未运行Steam或FAF游戏，不能把源码分析视为玩法验收。

## 可行结论

AI可以直接编写地图的scenario/save/options/script和独立Lua模块，也可以用参数、种子和规则驱动地形生成器。难点是生成后核验：合法二进制地形、资源闭包、可通行路径、出生空间、水深、各阶段波次、胜负和多人同步。当前成果是62张的参考目录、维护方法和可运行静态扫描器，**不是已经完成了一个全自动制图平台，也没有新地图实机通过**。

不要让语言模型凭空拼接`.scmap`字节。先使用格式解析器、编辑器或程序化生成器产生地形，再由AI制作玩法数据和脚本，最后在目标游戏验证。`.scmap`与`ScenarioInfo.map_version`是不同版本概念；v56/v60也不能简单等同于Steam/FAF。[FAF地图维护指南](https://github.com/FAForever/wiki-pages/blob/main/faf-version-guidelines.md)说明文件职责与格式差异。

## 先学习哪些现有玩法

| 目标 | 本包参考 | 必须一起理解的内容 |
| --- | --- | --- |
| 定时守点、普通波次 | Omega、5th practice、Experimental Factory | 初始化→计时→阶段单位表→数量计算→生成→命令→目标死亡/时间胜利；首次生成与准备计时分开。 |
| 少人合作、人数缩放 | practice、Center EE、Horde EE | 仅统计实际防守army；空槽、额外army、目标生命/回血可能同时被人数改变。 |
| 传送门攻防 | Black Sun、Extreme、Light、EpischeLAN | 门生成、门死亡计数、援军终止、胜利状态必须一致，不能只移植刷兵。 |
| 护送和分阶段扩区 | Escape、Run、Attack | 路点编号起点、连续性、目标存活、地形可通行、扩区/首领触发；不同地图的默认计数不能共用。 |
| 分路线波次与阵营切换 | Horde EE | WaveTable、WaveOrders、路线占用、空军和资源模块整套配对；新版的万古模式不是只换单位ID。 |
| 经济驱动敌军、竞争生存 | Endless、Survival of the Fittest、Anerle | 收入和击杀质量统计、敌方钱包、随机AI性格、玩家存活、胜利计分；不是按分钟固定波表。 |
| 战役式事件与多模块 | Rainmakers、Genesis of the Order、Stranded | 目标对象、初始存档组、事件调度、联盟、战役UI、资源生成、海陆空/空投模块；主脚本单独复制没有完整玩法。 |
| 可选MOD和纯原版分支 | Genesis、Desert Front、Voodoo New、Terror Lands、Onix Voodoo | 基础单位池始终有效；仅在检测到模组时加载其表；“仅模组单位”模式另有要求，不能称所有菜单组合零依赖。 |

复杂地图只作为结构参考。作者署名、素材来源和许可证须随改编保留；未提供明确许可的地图代码不作为可自由复制的开源模板，本知识库不上传原地图源码和资产。

## 新玩法的数据契约

先形成一份可验证的设计清单，再生成Lua。建议字段如下：

```json
{
  "target": "steam",
  "identity": "facn_example_survival",
  "revision": 1,
  "players": ["ARMY_1", "ARMY_2", "ARMY_3", "ARMY_4"],
  "extra_armies": ["ARMY_DEFEND", "ARMY_ENEMY"],
  "markers": {"objective": "FACN_TARGET", "enemy_land": ["FACN_LAND_1"]},
  "rules": {"build_seconds": 120, "victory_seconds": 1800, "max_active_enemies": 400},
  "phases": [{"at_seconds": 0, "interval_seconds": 20, "unit_ids": ["uel0106"], "count": 4}],
  "loss": "defence_object_destroyed",
  "win": "timer_elapsed_and_object_alive"
}
```

这只是数据设计示例；坐标、军队、单位和限制必须实际存在于所选地形/存档和蓝图库。敌军数量上限与刷新间隔都要有限值。设计里明确“击毁所有敌军才结束”还是“坚持到时刻即结束”，避免计时到了却仍刷兵、目标死后又显示胜利。

生成脚本前检查：所有marker在边界内；地面/海军出生位置可用；armies不同时进入普通大厅槽与ExtraArmies；事件只由sim运行；每个循环有等待或明确终止；不向空army发单位；重复回调不能重复结算；退出/失败后停止线程；随机数、遍历及全体玩家使用的文件保持同步。

## Steam 与 FAF 使用两个构建配置

| 层 | Steam配置 | FAF配置 |
| --- | --- | --- |
| 脚本/API | 核对实际安装`.scd`和原生接口；本机蓝图索引573种 | 固定已验证FAF版本，核对该版本源代码与实际挂载包 |
| Lua | 使用目标LuaPlus编译；本机旧Lua不接受把`...`直接转发为表达式 | 仍用FAF目标运行时检查，不假定普通Lua5.4可替代 |
| 单位 | 原版蓝图或明示的可选分支 | 可使用FAF单位，但必须记录新增ID和版本 |
| 地表/水面/物件 | 仅引用实际Steam资源，或随地图附带允许分发的素材 | 可使用FAF扩展资源，但要形成资源清单，不依赖作者机器上的其他地图 |
| 菜单 | 默认值和缺省值可靠；真实大厅显示/传值另测 | 验证FAF大厅的default、pref、值类型与版本 |
| 身份 | 独立目录/虚拟路径/修订，防止同名地图互相覆盖 | 独立构建目录，依发布平台规则设置版本 |

共用设计数据与算法，接口、单位、贴图和大厅适配按目标构建。**不要只把FAF地图改名就当Steam版，也不要断言两边所有地图都互不兼容。** [FAF加载代码](https://github.com/FAForever/fa/blob/develop/init_shared.lua)挂载原版与额外资源，兼容性取决于实际引用。FAF额外资源较丰富的方向有源码依据，但本机没有提供可用FAF安装；没有统计“FAF比Steam多多少张贴图”，也没有FAF运行验收。

## 地形和美术自动化的现实路线

1. 用纸面布局/参数清单定义通路、出生区、安全建造区、目标和水域；先形成可通行骨架。
2. 使用[Neroxis地图生成器](https://github.com/FAForever/Neroxis-Map-Generator)或[FAF地图编辑器](https://github.com/ozonexo3/FAForeverMapEditor)产生/编辑二进制地形。记录工具提交、参数、种子及输出哈希，不假设默认输出零依赖Steam。
3. 按目标资源白名单选择地表、法线、贴花、props和水纹；生成或导入高度图与蒙版。高度图通常比地形格数多一行一列，不能把512格图直接当作512×512高度采样。
4. 以资源类型解析`.scmap`中的路径和长度字段。改名需同时处理Lua路径和二进制资源路径；不能靠随意搜索替换改长短不同的字串。
5. AI生成Lua和波次表，运行静态依赖/蓝图/菜单核验，再检查各生成点的地形坡度、水深、出路、拥堵和攻击目标。
6. 分别完成Steam与FAF的默认、少人、空槽、非默认选项、后期、目标死亡/胜利和多人测试；只发布通过的目标配置。

[程序化素材工作流](https://github.com/FAForever/fa-automation-procedural-content)展示了高度图、蒙版、层纹理和贴花的转换组织方式，但该仓库已归档，只作为方法参考，不称仍维护的现成平台。编辑器里能看到素材不等于游戏包里带着该素材。

## 以后维修的最短路径

1. 在[代码地图册](SURVIVAL_CODE_ATLAS_2026-10-16.md)按名字找到逐图卡片，核对当前版本/文件哈希；旧卡片不得直接覆盖新文件。
2. 按症状选入口：加载失败查scenario路径/军队，首波查准备时间与生成，后期查升级波/新增单位，胜负查目标回调，贴图查`.scmap`引用，菜单查key/default/pref/消费者。
3. 先验证是地图、游戏版本、资源挂载还是其他MOD的问题。网上已关闭的问题只作为测试线索，不能当作当前故障证据。
4. 制作最小补丁、备份、严格升版、同步显示名，记录玩法是否有损失。使用目标Lua而非通用Lua编译器。
5. 更新卡片、已知问题、维护日志和测试证据；缺少实机或多人结果时保留“已修改待实测”。

可复用的只读扫描器：`python tools/scan_scfa_maps.py --maps <地图包> --game <Steam安装> --out <新的JSON路径>`。它可以记录哈希、常量导入和`.scmap`资源路径，但不执行Lua、不能证明动态路径或玩法正确。当前包上实跑识别62张与573种Steam蓝图。不要把扫描器的候选标记直接转成批量修复。


## 参考：受控的敌方据点增强（2026-10-20）

Insane v3按用户授权增加8套堡垒，是新玩法扩展，不能伪称恢复丢失的原单位。以目标方向构造局部坐标再旋转，读取生成点地形高程，检查原出生区和实际蓝图占地；按门阵营配置，难度只改有限的兵种/数量，保留原胜利目标。

护盾应复制每单位规格交给本机Unit.CreateShield，不直接改共享Blueprint.Defense.Shield；ShieldSize是直径，原生球形碰撞半径为Size/2。验证重复初始化、门死亡计数、首波和统计启动。Steam XEB2306为T3重型地面炮，四阵营*B2304为T3防空，不能凭ID序号猜用途。方法与边界见[实例](INSANE_GATE_FORTRESS_V3_2026-10-20.md)，50项模型检查不代表真实射击、寻路或多人验收。

### 后续密度迭代：保留实际刷兵坐标系

Insane v4用户截图反馈说明“脚本生成成功”不等于布局达到需求。增加数量时先明确建筑中心范围、各角色数量、护盾覆盖和出路；原生成在世界X/Z取离散偏移，不能只验证旋转后的局部正方形。v4采用最近主方向正交布局，保留世界±14出生方框和12宽正面出口；按半SkirtSize加绝对SkirtOffset作保守包围检查。盾覆盖还需考虑生成器之间和门/塔占地角点，水平模型不证明真实球形碰撞、地形高差、射击或寻路。密度提高须同时记录单位总数和性能/平衡待测，不能把“更多建筑”写成难度已经合适。见[v4实例](INSANE_GATE_FORTRESS_V4_2026-10-20.md)。

### 难度审计与紧凑据点的第二步

用户明确允许把波次出生放到防线外时，不再把原门旁刷兵位置当硬性要求。定义“核心位置、守备模板、关联出生区”三个数据，活门计数控制对应出生区，按波池最大占地分格。用目标安装的实际GetSkirtRect而非只用图标或Footprint；未显式Footprint需引擎补全，规划模型必须标假设。边缘核心用向地图内侧展开的模板，检查每处边界；紧凑后原版盾尺寸可能已足够，不靠扩大空罩代替交叉火力。

难度分开审计数量/最大与当前HP/武器伤害/盾HP/科技时间轴/目标援助，记录具体消费者与是否只改第1武器。连续读取GetHealth在SetMaxHealth后可能产生截断差异，单一替身模型不能证明原生HP；未来计算一次基准值再统一赋值。准备时间与科技阶段时钟必须明确是否相减；本机地图面板不使用地图default字段，需沿实际选择和传值路径查证。紧凑化还要检查核心死亡AOE/假核爆、最小射程空档、胜利目标是否包含火炮、全图总单位与性能。具体候选和边界见[Insane分析](INSANE_DIFFICULTY_LAYOUT_ANALYSIS_2026-10-20.md)，本轮未改地图。

### 检查安装目录的汉化覆盖

维护包已译不能证明安装副本已译，先固定用户指定扫描根并排除明确官方目录。按当前maputil实际路径规则确定活动options，在目标Lua中隔离求值后检查label/help/values.text/values.help；注释和未启用条目不是可见菜单，带LOC要查实际中文语言键。缩写、模式专名、数值与整句漏译分开。跨多张图反复出现的英文可能来自共享模组菜单，不逐图改系统设置。只有语言审计不执行玩法，也不因名字相似覆盖维护包版本。本轮实例见[42张安装地图核对](INSTALLED_ADVANCED_OPTIONS_CHINESE_AUDIT_2026-10-20.md)。

### 汉化实施与版本核验

只编辑活动options中的显示字符串，语义对比排除label/help/text后应与原表深度相同；包含default、分数表达式、重复键和顺序，不因为发现旧数值疑点顺手改玩法。场景仅map_version加1并比较其余字段、顶层version不变。保留作者星号而不擅写“默认”；按真实下拉控件宽度收短长中文，并保留原条件与组合信息。备份放扫描根外，部署后以实际文件再求值，对完整目录基线列出唯一变化集合。安装副本与维护包近似名或同版本不能直接等同，见[三图实施例](THREE_5IVER_OPTIONS_LOCALIZATION_2026-10-20.md)。
