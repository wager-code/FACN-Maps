# 生存地图维护：用户要求与后续执行约定（2026-10-21）

本页集中保存本轮用户的明确要求及后续纠正。开始修改生存地图前，必须连同仓库`AGENTS.md`、对应地图卡片和当前安装文件阅读。历史报告用于追溯，不可用旧方案覆盖后续已确认的要求。

## 范围与权限

- 当前操作对象为`E:/SCFA/maps/`安装副本：103个地图配置中61官方、42自定义，本轮识别35张生存/AOD。维护地图包62张是另一套文件，不自动同步。
- 官方地图及其原有设计直接跳过，不因为特殊人数、非方形地形、区域或路径标记判断损坏。
- 用户原话：“生存地图原本自带的一些设置，不能删除也不能改动……不然会影响游戏玩法”。原则是保留有效原功能，不借本次维护改波次、难度、目标、计分、科技时钟、核爆或其它无关机制。
- 后续用户对已经审计确认的开局单位重复链明确选择：“直接去掉旧的，以新的为主啊”。此指示覆盖该批重复实现的早期相加方案，不授权未经追踪就批删其它地图旧逻辑。
- 用户对Atoll和Brainsucka发布失败明确限定：“你只能改地图的文件，不能改软件的源码”。本次适配仅写地图文件，不改内容中心、网关或游戏程序；只读检查软件规则不等于获得修改许可。
- 此前隐藏自动版本显示曾有单独授权，只改既有第三方大厅增强包的一处列表逻辑；不能把那次授权沿用到当前发布修复，也不能错误记成“从未改过任何UI文件”。
- 修改前保存完整地图备份和SHA；移出已确认冗余的文件时备份必须留在地图发布目录之外。不要清理用户偏好、关闭游戏或修改其它目录来掩盖问题。

## 先检查已有功能，再决定修改

不能只看中文名称、截图或菜单Key是否相同。不同名称可能控制同一生成链；不同Key也可能重复生成。必须追踪以下完整链条：

`选项定义/注册/加载 → key与pref → default及values.key → 读取/解码/默认回退 → 初始化/回调/线程 → 单位生成/时机/对象 → 后续效果`

审计覆盖`options/scenario/script/save`、导入模块、辅助函数及实际活动入口；预放单位必须查`save.INITIAL`，字节码或动态依赖不能按文本未找到消费者就判无效。

| 情况 | 处理要求 |
| --- | --- |
| A：已有完全相同功能 | 复用正确且实际生效的一套，清理已证明冗余的定义与引用，不再添加一套 |
| B：已有类似功能但不完整 | 优先补全原实现；确需独立选项时说明缺口、语义、Key与调用关系 |
| C：名称类似而功能不同 | 保留有效差异，核对是否覆盖或重复执行；不能把ACU、SCU、剧情援军混删 |
| D：新旧代码冲突 | 先确认保留实现，再统一入口，清理无效定义、读取与调用，而不是只隐藏菜单 |
| 证据不足 | 报告具体差异，请用户确认关键语义；不擅自删除，也不把已有明确授权重复拿来询问 |

只有证明现有实现缺失或不能满足需求，才增加功能。修复采用最小范围，不顺手修改地图名称、修订号、单位平衡和其它设置；名称清理等专项要求按其明确范围另行处理。

## 开局准备时间

- 用户原话：“地图原来有开局准备时间的，在原来的基础上改不就行了”。已有准备选项必须复用、扩档或完善，不再额外列一项同功能准备时间。
- 有原菜单时沿用其Key、pref、默认值、旧值和旧值顺序；新增档位追加。没有原菜单时才保留单独的一项，并允许默认沿用原图。
- 菜单名称不带“新增”二字；保留“额外”时必须准确表示额外数量，不能掩盖两套重复生成。
- 固定时长显示统一用`m:ss`，包括`0:00`、`0:30`、`12:00`、`20:00`，不能12分钟以后改成文字分钟。“沿用原图（默认）”等非数值语义可保留。
- 分清分钟、秒和编码值；扩展菜单时同步检查允许值列表/解码器，避免菜单选了20分钟、脚本实际回退5分钟。
- 不叠加新旧等待、不重写全局时钟、不重置科技阶段，不将其它波次间隔一并更改。旧缓存Key不能继续覆盖合并后的原菜单。

## 副指挥官和工程师

用户要求两类独立选择数量、种族，也能四种族一起出。当前统一控制是：

| 控制项 | 当前设计 |
| --- | --- |
| 副指挥官数量 | 每个实际玩家、每个选中阵营0～20；默认0 |
| 副指挥官种族 | 跟随玩家/四族之一/四族一起，独立于工程师 |
| 工程师数量 | 每个实际玩家、每个选中阵营0～20；默认0 |
| 工程师等级 | T1/T2/T3；默认T3，数量0时不生成 |
| 工程师种族 | 跟随玩家/四族之一/四族一起，独立于副指挥官 |

四族数量1表示四族各1、该类合计4；两类都选四族20时每玩家最多160个额外单位。排除空槽、辅助军队及已失败军队，不重复按不同入口发放。必须核对碰撞/位置、归属和原地图局部单位规则；如Endless原赠送零自产，合并后不能无意丢失。

本轮8图确认重复后删20项旧开局控制及对应生成链，保留统一新控制；此结果不代表所有固定单位、主指挥官、剧情增援和特殊玩法都可删除。

## 主指挥官与特殊地图取舍

- ACU主指挥官与SCU副指挥官不同。先查预放INITIAL、正常InitializeArmies、空槽补发和额外SCU，不能仅按“指挥官”文字归为重复。
- `survival_5thdimension_practice`的“第一/二/三/四名指挥官阵营”实际控制空槽主ACU补发，不是生存排名。用户确认选择删除四菜单及空槽补发；保留正常玩家ACU、人数缩放和现有额外单位设置。
- `survival_5thdimension`原INITIAL每玩家8台四族主ACU。用户要求每玩家默认只留1台大厅所选阵营主ACU，更多SCU在高级设置选。已删除32台预放ACU并保留空INITIAL，复用原版按阵营回退生成，不另起生成器，也不先生成再炸掉。
- 上述删除范围只针对已确认地图和链条，不能擅自改其它地图的特殊主ACU或剧情。

## 地图名称与版本显示

用户要求：“地图名称不显示版本号……左侧信息里面可以显示”“手写的版本号也要去掉”。

- 地图列表显示基础名称；删除已确认手写的`v9/Version:N/Beta`等版本或发布后缀，并处理列表自动追加版本的显示来源。
- 实际`ScenarioInfo.map_version`保留，左侧信息仍可显示版本；隐藏名称版本不等于删除版本字段或降低版本。
- `4v4`、`5P`、`5thdimension`、`BlackBox 10`等身份/玩法数字不能当版本删除。
- 本次名称清理不重命名目录、内部文件或虚拟路径；未来确需重命名时另查所有引用、重名和兼容性，不能用历史命名规范扩大本次范围。

## 防守目标、沙盘与结算

用户纠正：目标开局存在，自己用指挥官爆炸与核弹故意摧毁，并非盟军主动攻击。不能记录成“目标未创建”或直接归因于联盟错误。

- 沙盘关闭普通歼灭条件检查，但地图仍可自行判胜/判负；不是所有生存图都只能手动退出。
- 分开验证目标死亡回调、胜负结果、刷兵/模拟终止、结算界面。`OnDefeat`不等于立刻结束整局或自动弹完整分数表。
- 保留地图所需沙盘，沿实际目标回调及错误日志查调用中断；不能为让游戏结束而直接切普通胜利条件，导致辅助军队或无ACU模式提前结束。
- 本轮对相关结算是调查，用户当局完整执行链未有日志证明，不能把源码存在调用说成实际已修好，也不能归并35图为同一故障。

## 必须实际执行的验证与汇报

1. 菜单无重复功能和重复Key；每个保留选项均有有效读取与执行。
2. 默认、0、至少一个非默认值，以及数量/阵营/种族/等级组合符合设计；多个入口不重复执行、不互相覆盖。
3. Lua使用目标游戏方言核验，检查导入、场景引用、Army、单位蓝图及生成位置。普通Lua解析器通过不能替代SCFA LuaPlus检查。
4. **选项文件必须在真实无库空环境加载**：本机maputil以`optionsEnv={}`执行，不能依赖`ipairs/table.insert`。地图文件错误也能阻断主菜单“多人游戏”入口，不能因为没改EXE就排除地图问题。
5. 完整备份、候选检查、部署后文件SHA与实际读取核验均记录；其它地图/官方文件保持情况可复核。
6. 菜单加载、游戏启动、首波、后期、胜负、单人/多人、内容中心扫描与云发布分别记录。不能进游戏时写“已修改待实测”；隔离替身和数据相等不称实机通过。
7. 报告给出表格：`选项名称 | 原有情况 | 处理方式 | 最终结果`，另列修改文件、删除的重复代码/入口、实际检查和待游戏验证项目。增加了代码本身不是验收结果。
